## 选择门判定（冻结协议）

- 默认选择：**fixed_time**（保守回退基线），改进声明：**False**
- capacity_aware_max_pressure：CI 上界 -0.906 < 0 ✓，改善单元 25/30 ≥ 21 ✓，**safety_eligible = False**（硬安全门失败）
- classic_max_pressure：改善单元 18/30 < 21 ✗，safety_eligible = False

### 硬安全门失败的事实（如实呈现）

场景 11（0.1s 步长窄路场景）在标定与加压流量下存在**跨算法的交叉口碰撞**：

| 算法 | 碰撞 run 数（normal 120 中） |
| --- | --- |
| fixed_time | 4 |
| classic_max_pressure | 5 |
| capacity_aware_max_pressure | 3 |

- 碰撞为交叉口穿越冲突（`collisions.xml` type=collision，事件位置均在路口入口
  道处），源于场景 11 官方多阶段配时下的合流/穿越行为，属**场景固有数据现实**，
  与算法无关；CA-MP 的碰撞记录为三者中最少。
- 冻结的候选门要求候选算法 180 run 绝对零碰撞——场景 11 使任何候选都无法
  满足该门，因此选择保守回退基线。门的修订（如相对安全门）属协议变更，须
  走 test-first 修订与独立复审，不得在看到结果后调整。

## 3. 扰动韧性

**解读**：CA-MP 在施工占道下旅行时间最优（67.20s，较基线改善 7.2%），且在
全部三类扰动下平均排队长度均为三者最低（3.78 / 3.44 / 3.53 m）——溢出门控
与容量归一化在拥挤与受限路网中最能发挥价值。

## 4. 选择门判定与诚实声明

冻结协议的默认选择门要求候选算法：①旅行时间 95% CI 上界 < 0；②≥ 21/30
场景-流量单元改善；③180 run 绝对零碰撞、零红灯违规、零非法相位转换。

- CA-MP：①通过（CI [-4.85, -0.91]）②通过（25/30）③**未通过**——
  场景 11 存在 3 个含碰撞 run。
- 场景 11 的碰撞为**跨算法**现象（fixed_time 4 个、classic 5 个、CA-MP 3 个），
  位于路口入口道的穿越冲突，属该 0.1s 步长场景官方配时下的固有数据现实；
  CA-MP 碰撞记录为三者中最少。
- 因此默认选择保守回退基线 `fixed_time`，改进声明为 False。门的修订属协议
  变更（如改为相对安全门），须 test-first 修订并独立复审，不在本轮进行。

## 5. 结论

1. CA-MP 在主要指标上取得统计显著改善：平均旅行时间 -3.65%（95% CI
   [-4.85, -0.91]秒），25/30 场景-流量单元改善，平均排队长度全场最低。
2. 韧性优势明确：施工占道（最严苛扰动）下旅行时间最优，三类扰动排队
   全部最低。
3. 安全记录三者最佳（碰撞 run 数 3 vs 4/5），但受场景 11 固有碰撞影响，
   未通过绝对零碰撞的保守选择门——如实呈现，不做选择性声明。
4. 全部 540 run 密封证据可复现：每个数字回链 `analysis_manifest.json`
   与具体 run 目录。
