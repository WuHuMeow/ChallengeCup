## Fix round 1 root causes

1. **Sealed scene identity:** the validated result response model carried only the sealed summary, while the browser read `summary.scene_id`. Real `summary.json` does not contain scene identity; the authoritative value is in the hash-bound `manifest.json`. The API therefore had no valid identity to serialize, and Comparison fell back to `unknown`.
2. **Reconnect race:** WebSocket open/close/error callbacks checked only the run ID and intentional-close flag. A superseded subscription for the same run could therefore mutate connection state after a successful reconnect.
3. **Safety metric omission:** Comparison's metric definition stopped after `collision_count` and `red_light_count`; it omitted `illegal_transition_count`, `harsh_braking_count`, `teleport_count`, and `potential_conflict_count`, and did not distinguish the three hard gates from the three observational counters.
4. **Uncertainty fail-closed behavior:** the page used a generic "uncertainty not reported" footnote and a "Formal evidence" presentation for individual rows. That did not clearly state that these are sealed individual-run rows rather than a formal matrix conclusion, nor that the authoritative 95% CI awaits Task 22.

## Implementation summary

- `experiments/evidence.py`
  - Added `EvidenceReader.load_result_evidence()` to read the exact `summary.json` and `manifest.json` byte pair, verify both against `hashes.json`, bind both digests into strict validation, and recheck stable file digests before returning.
  - Extended validation with an optional exact manifest digest while preserving `load_summary()` as a compatibility wrapper.
- `api/models.py`, `api/server.py`
  - Added required top-level `scene_id` to validated result list/detail models.
  - Derived it only from the validated sealed manifest after output-root containment; no path parsing and no summary trust.
  - Kept `run_dir` absent from list/detail responses and migrated the safety consumer to the enriched validated-result helper contract.
- `docs/api/openapi.json`
  - Deterministically regenerated. `scene_id` is now a required string in both `ResultListItemModel` and `ResultDetailModel`. `postman_collection.json` regenerated byte-identically and therefore has no diff.
- `web/src/api/client.ts`, `web/src/App.tsx`, `web/src/components/ComparisonView.tsx`, `web/src/components/HistoryView.tsx`
  - Made `ResultListItem.scene_id` required and consumed only that top-level identity.
  - Guarded every connection-state open/close/error callback with `subscriptionRef.current === subscription` in addition to existing run/intentional-close rules.
  - Rendered all six safety values with sealed `summary.units` count semantics; null/missing remains explicit rather than zero.
  - Labelled the first three metrics as hard safety gates and the last three as observational.
  - Labelled rows as sealed individual-run evidence and stated that formal 95% CI awaits Task 22's complete sealed 540-run matrix; no browser CI, error bars, significance, winner/default, or percentage improvement is computed or shown.
  - History displays `Scene {result.scene_id}` and the sanitized full result detail, including top-level scene identity without a filesystem path.
- `web/tests/judge-flow.spec.ts`, `tests/test_judge_api.py`
  - Updated the browser fixture so summary has no scene identity, result top level does, safety values are distinguishable `1..6`, and units are explicit counts.
  - Added the delayed stale-socket reconnect regression and API list/detail assertions for real sealed scene identity plus `run_dir` absence.
- `engine/runner.py`, `tests/test_runner_channel.py`
  - Published the actual current phase, phase name, and elapsed phase time in each realtime metrics event, with direct runner-channel regression coverage.
- `api/static/dist/*`
